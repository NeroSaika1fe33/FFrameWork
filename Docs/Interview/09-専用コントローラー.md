# 専用コントローラー制作

[五つの工夫の総覧へ](06-作品の工夫した点.md)

## 概要

ボタン・つまみ・フェーダーを備えた専用コントローラーを制作し、実際に手を動かしてリズム入力や画面上の操作を楽しめるようにしています。

紹介時は、実物の構造と Unity 側の入力処理をつなげて説明します。[コントローラー紹介図](../../Assets/Features/Sprite/Panel/OperationGuide/OperationGuide2.png)には、四つのリズムボタン、中央のエフェクトボタン、つまみ、フェーダー、スタートボタンを示しています。

## Unity 側の入力設定

| ゲーム内の操作 | アクション名 | 現在の入力バインディング |
| --- | --- | --- |
| 固定四キー | FixedLaneInput0 ～ FixedLaneInput3 | A / S / K / L |
| フリーレーンの押下 | FreeLaneInput | Space / Pointer の押下 |
| 判定枠の位置操作 | ArrowInputPosition | マウスの X 方向の変化 |
| 判定枠の幅に関する操作 | ArrowInputSize | マウスの Y 方向の変化 |

この表は Unity が受け取る入力を示しています。実機の各部品がどの入力を送るかは、コントローラー側の実装と合わせて説明します。配線やファームウェアは、この Unity プロジェクトには含まれていません。

## ゲームへ入力を渡す流れ

1. **入力を読み取る。** Input System が設定に従ってボタン状態や方向の変化量を取得します。
2. **ゲーム用の形式へ整理する。** InputManager が押下・保持・解放を区別し、ArrowInput が位置と幅に関する変化量を提供します。
3. **判定へ渡す。** LiveInputCollector が入力の種類と判定枠の範囲を組み合わせ、判定処理へ渡します。

長条では「一度押したか」だけでなく、「操作を続けているか」も必要になるため、入力の段階を区別して扱います。

## 工夫した点

実機の操作、画面の変化、音の変化を一つのプレイ体験として組み合わせています。実物を動かしながら画面と音の反応を示すと、操作の狙いを伝えやすくなります。

## 紹介文の例

> ボタン・つまみ・フェーダーを備えた専用コントローラーを制作しました。リズム入力と判定枠の操作を組み合わせ、手を動かして演奏する感覚を目指しています。
