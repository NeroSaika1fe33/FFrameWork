# 譜面・楽曲再生・ゲーム進行の同期制御

[五つの工夫の総覧へ](06-作品の工夫した点.md)

## 概要

リズムゲームでは、聞こえる音楽、画面上のノーツ、入力を判定する時刻を対応させる必要があります。本作品では、FMOD の再生時刻を基準にして譜面の時刻を求め、ノーツと判定を進めています。

OpenSekai の LiveLogic と Converter を基盤に、現在の音声再生・入力・表示へ接続しています。

## 処理の流れ

1. **楽曲の時刻を取得する。** FmodSyncedUnityTimer が FMOD から再生位置をミリ秒で読み取ります。
2. **譜面の時刻へ換算する。** LiveSceneController が秒へ変換し、開始時の待機時間やタイミング補正を反映します。
3. **ノーツと判定を進める。** LiveLogic が譜面情報、ノーツ、長押し状態を更新し、その譜面時刻で入力を収集・判定します。
4. **画面へ反映する。** 表示側がノーツの進行度を読み取り、表示位置などを更新します。

流れは、**楽曲の再生時刻 → 譜面の時刻 → ノーツ状態と入力判定 → 表示更新**です。

小節・拍子・BPM は秒数へ換算します。例えば BPM 120、四拍で一小節の場合、一小節は二秒です。BPM や拍子が変わる場合は、区間ごとに時間を計算します。

最初は LiveSceneController.Update() 内の GetCurrentMusicTime() と liveLogic.OnUpdate(...) を見ると、時刻の取得元と受け渡し先を確認できます。

## 工夫した点

音楽とゲームが別々に時間を積み上げないように、共通の時刻に対応させています。ポーズ時は音楽と演奏ロジックを止め、再開時は ResumeLiveNow() と SeekMusic() で位置を合わせます。

現在の入力はフレーム単位で読み取っています。音楽を時刻の基準にしていても、入力精度がフレームレートの影響を完全に受けなくなるわけではありません。

## 紹介文の例

> 既存の演奏処理を基盤に、FMOD の再生時刻へ譜面進行・入力判定・ノーツ表示を対応させています。BPM の変化や開始時の待機時間も考慮し、楽曲とゲーム進行を合わせています。
